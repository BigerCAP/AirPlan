## 学

- 袁哲生 小说集《寂寞的游戏》  ，早些时间已经阅读，感受”早熟的人通常都晚熟“中的另一个情绪（内心抑郁）
- 先找到困扰自己的问题，再想办法寻找工具解决它，永远将==注意力==放在自己身上，被我们普遍忽视的真相：并不是生活变得贫乏了，而是我们消费一切的速度太快了。阅读、进食、学习、感受——当默认速度被调到最高档，意义与愉悦来不及抵达。放慢你的消费速度，必然会改变你想要消费的东西。
    -  消费某种情绪或者实物（表达 - 真实 - 强大） VS （表达 - 寻求关注 - 不够幸福 - 弱小）
- 内耗的逻辑是做对比，比如：二十年前我就应该读那本书 VS. 二十年前我没有读那本书，结论就是二十年前我本该大赚一笔，结果我在二十年前大损一笔，一得一失之间，就可以给自己上皮鞭滴蜡油了。对于内耗和自我折磨可能有瘾。它能给人带来做了一点什么的虚假感觉，这样也就能带来一种合格的逃避---在现实世界里继续采取行动是艰难的，去面对真实是苦涩的，但是自我鞭笞又省钱又省电，而且暗中会觉得很爽。
    - 适度的反思是必要的，而反思的目的是为了现在就去改变，不是用过去来惩罚自己。不经意间错过是人生常态，还好一切都在继续，缘分的果实也还在慢慢成熟，你对它得有一点点信心，你对自己也得有一点点耐心。

## 阅

- 《FalconFS: Distributed File System for Large-Scale Deep Learning Pipeline 》
    - 论文地址：https://arxiv.org/abs/2507.10367  
    - GitHub 项目：https://github.com/falcon-infra/falconfs  
    - 应用场景：解决在大规模深度学习训练（特别是海量小文件，如自动驾驶、CV 领域）中，因传统文件系统（如 CephFS, Lustre）不仅需要客户端（训练节点）缓存大量元数据（Metadata），而且由于训练时的随机访问（Random Access）特性导致缓存命中率极低，最终造成训练节点内存被大量占用且I/O 性能低下的问题。
        - 该论文是基于华为鸿蒙智驾 + 数据存储 + Ai 训练场景构建实际存储结构、解决实际问题。降低 Client SDK 存在感（增加通用能力）、
    - 解决内容：针传统 FS（如 JuiceFS、Ceph）喜欢在客户端（Client）做缓存加速。但在 DL 训练中，每个 Epoch 都在随机读不同文件，缓存几乎没用，反而占用了宝贵的内存（本来是给 PyTorch/TensorFlow 用的）。
        - **Client 不存任何元数据**。所有路径解析（Path Resolution）全部移交给服务端（Server）处理。客户端只负责发请求“我要 `/data/img/1.jpg`”，服务端直接返回文件句柄或数据。 **VFS Shortcut**。它直接拦截了 VFS 的分步查找逻辑，一次性将**完整路径**发送给服务器（MNode）。服务器端利用高性能索引直接返回结果。这种方式将多次网络请求合并为一次。
        -  **惰性命名空间复制（Lazy Namespace Replication）**：让所有元数据服务器（MNode）都持有一份完整的“目录结构副本”。这样，Client 无论问哪个 Server，那个 Server 都能自己在本地算出文件在哪，不需要在 Server 之间踢皮球（消除 Server 间的 RPC 跳转）。
    - 主题优势：【论文内提供了一部分测试数据】
        - 相比于 **S3**，FalconFS 提供了真正的文件系统接口（POSIX）和极低的元数据延迟（List/Open 操作快得多）。
        -  相比于 **JuiceFS**，FalconFS 在**数据集规模远大于内存**的场景下（例如 10TB 图片数据训练），不会因为客户端缓存频繁失效（Cache Thrashing）而导致性能崩溃
